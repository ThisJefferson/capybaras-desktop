# Capybaras v0.0.2-alpha

**A calm herd of helpers that ask before they act.**

> Pre-alpha. Nothing is installable yet. The safety machinery now exists end to end; the interface does not.

## What's new since v0.0.1-alpha

**The policy layer — the gates now work.** `gate(action, context)` returns one of three answers: `proceed`, `ask`, or `dry_run`. That is the whole product, reduced to a function.

**A grant store.** Remembers that a human approved *this* action against *this* target, expiring after 30 days.

**Community documents** — `CONTRIBUTING.md`, `SECURITY.md`, `CODE_OF_CONDUCT.md`, `FUNDING.yml`, and issue templates.

**Brand assets** — six SVGs: four capybara states (sleeping, listening, working, needs-you), a six-capybara herd strip, and a 512 px app icon. Coral is reserved exclusively for the "needs you" state.

**Packaging and signing research** — a 31 KB engineering document. It changed three things in the plan, listed below.

## The rules, each with a test

These are the guarantees that make the product worth trusting. Every one is enforced in code and covered by the suite:

- **A remembered grant satisfies a `confirm` and nothing else.** A hard gate is **never** satisfied by memory — not after one approval, not after a hundred. There is a test named for that rule in capitals.
- **Dry run can only add caution.** It never turns an `ask` into a `proceed`.
- **Grants are scoped to one action against one target.** Wildcards are structurally impossible — the store refuses to hold one.
- **Approval requests carry every reason, not just the first.** If an action is off-limits *and* touches 1,200 rows *and* is irreversible, the human sees all three.
- **The model has no code path that creates a grant.** `record()` demands human provenance *and* a classification that already permits remembering, so a manipulated agent cannot be talked past the classifier.

## Corrections to things previously stated in this repository

- **The Microsoft Store developer account is free.** Microsoft removed the registration fee for individual developers in September 2025, and for companies on 7 May 2026. This repo previously budgeted **$19**; the correct figure is **$0**.
- **Azure Artifact Signing does not grant instant SmartScreen reputation.** Third-party marketing claims it does; Microsoft's own documentation says reputation is built over time. So the paid path buys less than advertised, and the free path buys more.

Net effect: the entire distribution budget is now roughly **$0**, which makes the donation model trivially sustainable.

## A real architecture change

**MSIX packages do not support traditional Windows Scheduled Tasks.** The Gateway currently auto-starts via a Scheduled Task; under Store distribution that mechanism does not exist and must become an **MSIX Start-up Task**. This changes how the Gateway is supervised at boot — it is not a packaging detail.

## Known unverified risk

Whether a bundled **Node sidecar** behaves correctly inside an MSIX *full-trust* package. The available evidence is a composite of separately-documented parts; no source documents MSIX + Tauri sidecar + Store submission together.

**The Phase 2 spike exists to answer exactly this**, before any packaging work begins.

## Also known

- GitHub Actions emits a deprecation notice because `actions/checkout@v4` and `actions/setup-node@v4` target Node 20, which runners now override to Node 24. Cosmetic; the job passes.
- `CODE_OF_CONDUCT.md` has a placeholder enforcement contact awaiting a real address.

## What's next

**Phase 2 — the viability spike.** A throwaway prototype answering whether a Tauri window can cleanly supervise a Node sidecar inside an MSIX full-trust package. If it can, packaging proceeds. If it cannot, the packaging strategy changes — and it is much better to learn that now than in month four.
