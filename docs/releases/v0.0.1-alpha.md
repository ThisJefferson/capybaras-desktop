# Capybaras v0.0.1-alpha

**A calm herd of helpers that ask before they act.**

> Pre-alpha. Nothing is installable yet. The safety machinery exists; the interface does not.

---

## What this release contains

**The risk classifier.** Every proposed action is classified into one of four tiers *before it runs*:

| Tier | Behaviour |
|---|---|
| **silent** | runs quietly — reads, searches |
| **notify** | runs, then tells you — creates |
| **confirm** | stops and asks you — deletes, edits, moves, sends, runs a command |
| **hard gate** | needs a typed confirmation — mass operations, irreversible change, money, secrets, security config, protected targets |

Hazard rules cover blast radius, reversibility, egress, motivation taint, destructive command patterns, protected targets, secrets, money, and security-config changes.

## Invariants

These are properties of the design, not features:

- **Escalation only.** Rules may raise a tier. Nothing lowers it.
- **Classification is the system's, not the model's.** A manipulated agent cannot argue its way down a tier.
- **Unknown fails safe.** An unrecognised tool requires consent rather than being treated as harmless.

## The acceptance test

This project has one criterion that matters. It encodes the incident of **23 July 2025**, when an AI coding agent deleted a production database *during an explicitly declared code freeze* — destroying data belonging to more than 1,200 executives and 1,190 companies — and then misreported what it had done.

> An agent with delete rights, told not to touch production, acting during a freeze, must be **hard-gated**, require a **typed confirmation**, and never be rememberable as "always allow."

**It passes.** Capybaras would have stopped it.

## Notable finding

**The acceptance test caught a real defect on its first run.**

The classifier originally recorded a reason *only when the tier moved*. So an action that was simultaneously off-limits, 1,200 rows, and irreversible reported exactly **one** reason: *"off-limits."*

That is the precise failure this project exists to prevent — a human approving something dangerous while being shown only the first thing that made it dangerous. Tier and reasons now compute independently. Recorded as `DECISIONS.md` D10.

## What's next

**The policy layer** — binding the classifier to a grant store (scoped, expiring, human-only, never grantable by the model) and a dry-run mode. That is what turns a classification into an actual gate.

After that: the Tauri shell spike, then the approval interface.
