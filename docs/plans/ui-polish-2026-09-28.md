# UI polish — audit and upgrade plan

**Date:** 2026-09-28
**Scope:** the graphical interface only (`apps/desktop/web/index.html`, `app.css`, `app.js`, `design/tokens.json`).
**Specification:** `docs/plans/ui-polish-brief.md`. **Extends:** `BRAND.md`, `docs/plans/M4-visual-design.md`.
**Boundary:** no change to business logic, agent behaviour, the sidecar, the Rust shell, permissions, data models, API calls or security decision-making. Frontend-only adjustments are called out where they occur.

Baseline measured before any change, on `c1a41cc`:

| Gate | Result |
|---|---|
| `npm run verify` | green — 382 tests / 14 files, typecheck clean, onboarding path PASSED |
| `npm run verify:ui` | PASSED — 6 agents, card present, tokens resolved (`#0F5C63` / `#F2705A`) |
| `npm run verify:acceptance` | PASSED — scenario halts, cannot proceed without a click |

The interface is three files and ~48 KB, so the audit is a close read of all of it plus a rendered look at `card-verify.png`, `onboarding-first-reply.png` and `acceptance-halt.png`.

## 1. What is wrong

### Structure and navigation

1. **There is no app shell.** `index.html` is a flat stack of eight `<section>`s with no header, no navigation, no page context and no measure. The `h1` is the product name at 20 px; every section is an equally weighted `h2` at 16 px. A reader cannot tell which surface is the product or where they are.
2. **The first screen is dominated by developer plumbing.** Four `dt/dd` rows of mono text — shell pid, a raw `C:\Users\…` state path, sidecar pid, job object — sit above the thing the product exists for. The path is `word-break: break-all`, so it is the loudest text on the page.
3. **The approval card is in the flow, not an overlay.** The single most important moment in the product renders mid-scroll, below six other sections, with no scrim, no focus management and no entrance motion. Keyboard focus is never moved to it; a keyboard user must Tab through the whole document to reach the two buttons.
4. **The herd is buried.** It sits below the meter with no heading, renders six 56 px wave tiles at 10 px caps, and its `title` attribute is hover-only.

### Typography, colour, spacing

5. **Body text is 14 px.** `BRAND.md` §5 says "16 px minimum body text" for a non-technical, often older audience. The interface has never met its own stated floor.
6. **The scale is leaked.** `app.css` hard-codes `10px` and `11px` (`.agent__state`, `.log`), bypassing the token ramp. `h1` (20 px) is smaller than `.card__headline` (24 px), so the page title loses to a component.
7. **No display style.** `--typography-family-display` is identical to `--typography-family-ui` and is used in exactly one place. There is no weight, tracking or size separation between product-level moments and body text.
8. **Spacing is ad hoc.** Sections carry `margin-top: var(--space-6)` with no common rhythm; the grid gaps inside the readouts differ from the gaps between sections; `body` padding has no max measure, so lines run the full window width on a wide screen.
9. **No semantic status family.** Status is two classes, `.ok` and `.bad`, both of which map to brand accents. `.bad` reuses **coral**, which `BRAND.md` and D18 reserve for exactly one meaning — *"a capybara is waiting for you"*. A stopped sidecar is currently painted in the reserved colour. There are no chips, no icons, no shape cues: meaning is carried by colour alone.
10. **The herd states are colour/opacity only.** Dozing is 35 % opacity, listening 75 %, working 100 %. That is precisely the "never rely on colour alone" failure the brief names, and the sixth state label is unreadable at 10 px.
11. **One surface, no depth.** Cards, banners, warnings and reply boxes each invent their own border, radius and background. There is no elevation discipline and no consistent border tone.

### States

12. **Loading is the word "loading".** Both readouts render `<dt>loading</dt>`, the model `<select>` renders empty, and the log renders blank — no skeletons, no layout reservation, so content shifts in when data lands.
13. **Empty states are one grey sentence** (`Nothing remembered yet.`, `The model list has not been loaded yet.`) with no next action and no explanation of the surface's purpose.
14. **Errors are a `<p class="hint bad">`** — a 12 px grey line at the bottom of a panel, and, for the reply, a paragraph in a container that has no `role`, no icon and no "nothing was changed" reassurance even though `BRAND.md` §6 calls that sentence the most important in the product.

### Motion

15. **Motion is two one-off keyframes.** `capy-work` and `capy-sign` carry hard-coded durations and are the entire motion language. There is no acknowledge/settle/confirm vocabulary, no panel entrance, no chip morph, no resolve confirmation, and nothing consumes `--motion-duration-*` beyond the two herd tiles.
16. **Reduced motion is handled by amputation.** `transition: none !important` removes feedback instead of substituting instant state change, which the brief explicitly forbids.

### Responsive and accessibility

17. **There is not one media query** except `prefers-reduced-motion`. The layout is a full-width column at 320 px and at 2560 px. The dev console, the readout grid and the card are all cramped on a phone.
18. **Accessibility gaps:** the card is not `role="dialog"` / `aria-modal` / `aria-labelledby`; the failure banner is a bare `div` with no `role="alert"`; the reply and the meter have no `aria-live`; buttons have no visible focus ring (only the phrase input does); the herd has an `aria-label` but no visible heading; the model `select` has a label but the label and control are separated by a flex row that reorders them at narrow widths.

### Performance

19. `setInterval(refreshStatus, 5000)` rebuilds four DOM rows unconditionally every five seconds — including while the window is hidden — and each rebuild can reflow the mono path text.
20. `filter: brightness(1.12)` on hover, and a `box-shadow` interpolated inside an `@keyframes` animation on the needs-you tile, are both compositor-hostile; the tile animates a paint property every 1.4 s.
21. No `contain`, no `content-visibility`, no `will-change` discipline; screenshots are 240–320 KB at DPR 2.

## 2. What will change, in what order

Six stages, one commit each. Every stage keeps `npm run verify`, `verify:ui`, `verify:acceptance` and `verify:onboarding` green.

### Stage 1 — Tokens (commit `feat(ui):`)
Extend `design/tokens.json` and regenerate `tokens.css`. Nothing visual changes on its own.

- **Colour:** add a real semantic status family — `state.caution` (sunset amber), `state.danger` (a deep red distinct from coral), `state.info` (muted navy/stone) — plus `state.success` (existing leaf) and the unchanged `state.needsYou` (coral). Coral keeps exactly one meaning. Add surface/border tones for bordered panels.
- **Typography:** add `2xs` (11 px) so nothing is hard-coded; add a `display` size step and a tracking set for caps labels.
- **Spacing:** keep the 4/8 grid; add the two steps the layout needs so no section invents a gap.
- **Radii/elevation:** add the one missing radius step and a `2`-step elevation used by the overlay.
- **Breakpoints:** declared as documentation (`breakpoint.tablet`, `breakpoint.desktop`, `breakpoint.wide`). Media queries cannot read `var()`, so the literals appear in `app.css` with the token named in a comment.
- **Motion:** keep the existing durations and add a panel duration and a settle easing; add a `layers` scale for the overlay stack.
- **Focus:** a token pair for the focus ring (width/offset/colour) so focus is one decision, not seven.

### Stage 2 — Shell, typography and spacing (commit `feat(ui):`)
Restructure `index.html` into an app shell **without changing a single id that a harness reads**:

- A sticky `header` with the calçadão strip, the wordmark, the tagline, a section nav and a compact always-visible money figure (BRAND §6: money always visible).
- A `main` grid: workspace column + hero rail. The herd moves into the rail as the identity element; DOM order stays herd-first so mobile reads it first too.
- Type scale applied: body at 16 px, a real display step for the wordmark and the card headline, section headings at `lg`/600, labels at `sm`, helper at `xs`, caps status labels at `2xs` with tracking, code at `sm` mono. Measure capped at ~72 characters.
- One spacing rhythm across every section; the readouts stop being the visual ceiling.

### Stage 3 — Components (commit `feat(ui):`)
- **Buttons:** primary / secondary / ghost / danger, plus loading and icon-only, with hover, active, focus-visible, disabled and busy states. `#btn-hold` stays the filled primary and `#btn-go` stays secondary — the acceptance test asserts the label and the visual review asserts the primacy.
- **Inputs:** label above control, helper below, one focus treatment, inline error, and a select that keeps its label attached at every width.
- **Navigation:** active-section highlight via `IntersectionObserver` with a no-JS fallback; the nav becomes a scrollable chip row under the tablet breakpoint.
- **Status and risk family:** one chip component with colour + icon + label + shape, used for the herd states, the shell/sidecar/job readout, the card tier and the balance. Coral appears only for needs-you; danger never uses coral.
- **The herd:** keep one character design, six accents, fixed slots; add a visible heading, a state legend, and a per-agent accessible description that does not depend on hover.
- **Data views:** the status readout becomes a labelled stat grid with the raw path demoted to a copyable, secondary line; the meter becomes a stat row with the balance labelled by scope, as it already is.
- **Overlays:** the approval card becomes a focused overlay — scrim, `role="dialog"`, `aria-modal`, `aria-labelledby`, focus moved in and restored on close, `Escape` = hold on (the safe action), and a bottom-sheet presentation on mobile. **Frontend-only adjustment:** a sibling scrim element driven by CSS from the card's `hidden` attribute, so `app.js` keeps toggling exactly the one property it toggles now.

### Stage 4 — States (commit `feat(ui):`)
- Skeletons with reserved height for the status readout, the meter and the model list.
- A deliberate empty state per surface: one icon, one sentence of purpose, one next action.
- Errors: a calm inline error component with an icon, the plain sentence, and the standing "nothing was changed" contract where the surface is destructive; the engine-down banner becomes `role="alert"` and moves to the top of the shell.

### Stage 5 — Motion (commit `feat(ui):`)
- A small motion vocabulary in one place: acknowledge (120 ms), transition (200 ms), settle (260 ms spring-ish), panel (380 ms), ambient (4–6 s).
- Recognisable moments: card entrance (settle + scrim fade), reply arrival (opacity + 4 px rise), chip morph between herd states, a single confirmation nod when an approval resolves, the calçadão wave as a thin indeterminate progress line under the header while a call is in flight, and the existing dozing breathing made slower and subtler.
- `prefers-reduced-motion` substitutes opacity and instant state change instead of deleting feedback.

### Stage 6 — Responsive (commit `feat(ui):`)
- **Desktop (≥ 1100 px):** two columns, sticky header, sticky hero rail, full-density readouts.
- **Tablet (720–1099 px):** single column; the rail becomes a horizontal herd strip; the nav becomes a chip row; panels lose their max-width cap.
- **Mobile (< 720 px):** focused single column, the card as a bottom sheet with a sticky action bar, 44 px minimum touch targets, the dev console collapsed behind a disclosure, no cramped data grid — readout rows stack into label/value pairs.

### Final
- Update `STATUS.md`. Push `main` (fast-forward only, no force) once every gate is green.

## 3. What I am deliberately not changing

- **Business logic, the gate, the classifier, permissions, grants.** Untouched.
- **The sidecar, the Rust shell, the protocol, the event and command names.** The seam check in `verify-onboarding.mjs` reads `app.js` for `invoke(...)`/`listen(...)` names and requires each to exist in the shell; no new command or event is introduced.
- **The brand palette values and the four state names.** Settled in `BRAND.md`; D18 settles one character × six accents. Extended, not revised.
- **Coral.** Stays reserved for needs-you. Nothing else may use it, including errors — that is the change *to* `.bad`, not a change to the palette.
- **The copy strings the harnesses assert.** `Not connected yet.`, the browser sign-in sentence, `N models available.`, the meter labels `model calls` / `tokens` / `spent` / `left (whole account)`, `Hold on`, the hard-gate warning, `Enter` = hold on. Digit-free where the tests require it.
- **`textContent` for everything remote-derived.** No `innerHTML` is introduced anywhere, including for the model catalogue.
- **CSP.** `script-src 'self'` holds. Everything stays in external files.
- **No new files referenced from `index.html`.** The two CDP harnesses serve a fixed `STATIC` map (`tokens.css`, `app.css`, `app.js`, `harness-bridge.js`); a new stylesheet or script would 404 there and silently change what the harnesses review. Everything goes into the four existing files.
- **No fonts, no icon library, no framework, no CDN.** `M4-visual-design.md` step 2/3 wanted bundled OFL fonts and Lucide; both need new files, so both stay on the remaining-polish list. Icons are drawn as small inline SVG built with `createElementNS`, the technique `app.js` already uses for the herd art.
- **The dev/acceptance console.** It stays in the product surface and stays reachable, because `verify:acceptance` drives it. It is made visually subordinate, not hidden.
